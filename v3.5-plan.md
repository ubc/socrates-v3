# Socrates v3.5 Development Plan

## Introduction

This document outlines the plan for updating the Socrates WordPress plugin (v3.5). The primary goals are:

1.  **Update Core Dependencies:** Refresh the LLM client libraries (`openai-php/client`, `alle-ai/anthropic-api-php`) to their latest versions to leverage new features and improvements.
2.  **Add Ollama Support:** Integrate Ollama as a third Generative AI provider option, allowing users to connect to local or remote Ollama instances.
3.  **Implement Robust LLM Response Handling:** Refactor the "Source Material" / "News of the Week" (NOTW) feature to request and parse JSON responses from LLMs instead of relying on specific text formats. This will improve reliability and data integrity. This change will only apply to backend processes; the front-end chat feature will continue to use streaming text responses.

This plan provides step-by-step instructions intended to be clear even for developers new to this plugin.

## Plugin Overview: Socrates v3

Socrates v3 is a multifaceted WordPress plugin designed primarily for educational contexts, combining interactive Socratic dialogues with automated content curation and research features. Its core components include:

1.  **Socratic Dialogue Chat:**

    - Provides a front-end chat interface enabling users (e.g., students) to engage in a Socratic dialogue powered by a configured Large Language Model (LLM).
    - Supports multiple LLM providers (currently ChatGPT via OpenAI and Claude via Anthropic, with Ollama support planned). API keys and model choices are configured in the plugin settings.
    - Administrators define the initial system prompt (`socratic_socratic_starting_prompt`) that guides the LLM's persona and questioning style, as well as the very first message the user sees (`socratic_socratic_initial_reply`).
    - The conversation flow is managed via AJAX (`handle_socrates_ajax`), processed by backend PHP classes which interact with the selected LLM through a central dispatcher (`Socrates_Send_LLM_Request`).

2.  **Source Material Curation & "News of the Week" (NOTW):**

    - Acts as a research and content curation tool.
    - Fetches articles from a list of administrator-defined RSS feeds (`socratic_feeds`) on a configurable schedule (`socratic_link_collection_cadence`).
    - Uses the `Readability` PHP library to attempt to extract the main content and create an excerpt from fetched article URLs.
    - Sends article titles and excerpts to the configured LLM for analysis. This analysis is guided by a separate system prompt (`socratic_notw_starting_prompt`), typically asking the LLM to rate the relevance of each article to specific topics/categories (`socratic_categories`) and assign a score/confidence level.
    - _(Current)_ Parses the LLM's formatted text response to extract scores and categories (`Socrates_Fetch_Feeds::convert_llm_response_to_array`).
    - _(Planned)_ Will be updated to request and parse structured JSON responses from the LLM for increased reliability.
    - Stores links that meet a minimum score threshold (`socratic_minimum_threshold_score`) as internal "bookmarks" (likely in the database, possibly as custom post types or options).
    - Can automatically generate a "News of the Week" post (`socratic_notw_day`, `socratic_notw_post_category`) summarizing the curated links, grouped by their assigned categories.

3.  **Contextual Link Integration:**

    - Connects the Socratic Dialogue and Source Material features.
    - Optionally (`socratic_hide_links_in_reply`), relevant links curated by the NOTW process can be automatically selected and displayed to the user within the Socratic chat interface alongside the LLM's replies, providing additional context or reading material (`socratic_links_preamble`).

4.  **Architecture:**
    - Employs separate classes for handling interactions with different LLMs (`Socrates_LLM_Chat_Gpt`, `Socrates_LLM_Claude`, planned `Socrates_LLM_Ollama`).
    - Uses a central dispatcher class (`Socrates_Send_LLM_Request`) to manage client instantiation and request/response flow based on plugin settings.
    - Settings are managed via a dedicated class (`Socrates_Settings`) and stored as WordPress options.
    - Relies on external PHP libraries managed via Composer (`composer.json`), including LLM clients and `Readability`.
